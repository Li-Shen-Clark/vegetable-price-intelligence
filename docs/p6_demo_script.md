# P6 五分钟作品集演示脚本

## 演示目标

让招聘方在五分钟内看到三个能力：

1. 能把经济问题转成可检验的数据与模型契约；
2. 能把模型结果转成 Pricing 工作流，而不是停在 notebook 指标；
3. 能对 partial release 和 no-go 做诚实、可审计的产品降级。

演示不打开原始 CSV/Parquet，不展示本地文件路径，不称为实时系统。所有页面均为 2014–2022 历史回放。

## 演示前准备

- 打开 `/case-study` 作为起点；
- 另备 `/forecast`、`/alerts`、`/procurement`、`/propagation` 四个标签；
- 使用现有本地授权数据；如果只有 GitHub clone，则只演示 `/case-study` 和代码/文档；
- 不现场运行训练或 final test。

## 0:00–0:40｜一句话与决策链

**页面：** `/case-study`

**说：**

> 这是一个 Pricing Intelligence layer，不是自动定价器。我从 868 万条批发市场报价建立可追溯的城市价格，再把它变成价格预期、涨价复核、采购成本情景和共同冲击证据。真正的 pricing engine 仍负责客户、库存、合同、利润和审批。

指出 P0→P5 决策链和正式 release states。不要逐项讲技术栈。

## 0:40–1:30｜预测：展示 partial release

**页面：** `/forecast`

**操作：** 选一个模型发布切片，再切换到一个 baseline fallback 切片。

**说：**

> 我没有只展示平均 WAPE。模型相对最佳简单基线总体改善 6.30%，但不同产品和跨度差异很大，所以 release matrix 逐切片决定模型、区间、point-only 或 baseline fallback。下游必须保留这个标签。

**必须指出：** Historical backtest；不是当前报价；区间未发布时保持为空。

## 1:30–2:20｜预警：展示行动阈值

**页面：** `/alerts`

**操作：** 保持默认历史真阳性事件，指出概率、阈值、提前量和城市范围。

**说：**

> 预警是独立分类问题。阈值只在 validation 的 FPR≤10% 条件下选择。Final recall 是 37.69%，FPR 9.99%，平均提前 7.18 天；但 precision 只有 21.31%，所以它只创建人工复核队列，不能自动调价。

## 2:20–3:20｜采购：把预测变成成本

**页面：** `/procurement`

**操作：** 展开一个候选成本，调整一次运输费率或风险偏好。

**说：**

> 这里把 P2 真正发布的模型或基线价格，加上估算运输、损耗、预测/历史残差风险和可靠性，形成到岸成本。36 组敏感性用来判断推荐是否依赖单一参数，而不是宣称最低价城市就是最优供应商。

**必须指出：** 城市中心估算距离、无真实运费/供货能力、不执行采购。

## 3:20–4:20｜共同冲击：展示 no-go

**页面：** `/propagation`

**操作：** 先指向双证据链中的 1,481 → 776 共同因子校正，再看方向性候选的 FDR 与 sealed final-test 门槛，最后查看共同冲击时间线和城市暴露 Top 10。

**说：**

> 这是我最看重的方法论案例。即使做了 FDR，未控制共同冲击时仍有 1,481 条同时关系；剔除季节和 leave-one-out 全国共同变化后降到 776，减少 47.6%。独立的方向模型再对 2,736 个事前候选做产品内 BH-FDR、validation 和 bootstrap。15 条边进入封存 final，但只有 4 条改善为正，中位改善 −1.39%，所以我发布 0 条方向边。产品只保留共同冲击和城市暴露，避免把共享运动或样本内显著误写成可执行的 Pricing 信号。

**不要做：** 不点名 4 条 final 正增益边作为“成功案例”，不称为因果传播。

## 4:20–5:00｜岗位价值与收尾

**页面：** 回到 `/case-study`

**说：**

> 这套项目体现的是端到端 Pricing problem solving：先定义信息集和基线，再评估不确定性与错误成本，最后把证据路由到成本、margin、供应和报价复核。弱模型会回退，高级假设会被 final test 否决。若进入生产，我下一步会接真实成本、库存、客户合同、销量和审批结果，而不是先增加算法复杂度。

## 演示失败时的恢复话术

### 本地数据没有载入

> 公开仓库故意不包含数据。Case Study 和 CI 可在无数据模式运行；完整分析页面需要授权的本地历史数据。我可以直接用 evidence matrix 讲解每项正式结果和验证边界。

### 页面加载慢

> 浏览器数据按产品拆分，本地首次加载可能需要片刻。我先用 Case Study 解释 release governance，再返回该页。

### 被追问“为什么不公开数据”

> 当前没有确认数据的再分发许可，所以仓库只公开代码、配置、测试和聚合方法结论。这个边界由 Git ignore、历史扫描和 CI 契约共同执行。
